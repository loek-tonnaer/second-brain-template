# second-brain

Plain-Markdown personal knowledge base for projects, tasks, and ideas. Browsed and edited in Obsidian by the user and by Claude Code across sessions. Optimized for quick capture and for efficient machine editing, not for long prose.

## Structure

```
Projects/<slug>/
  description.md  frontmatter (status, type, started) + one-paragraph description + links
  tasks.md        open tasks only (the file the AI reads by default); optional `## Subproject` sections
  archive.md      done tasks (only read when history is asked for), same `## Subproject` sections
  ideas.md        project-specific ideas (created on first idea)
  roadmap.md      optional long-term plan (created only when needed)
  notes/          optional deeper notes/specs
Ideas/          general ideas not tied to a project, one file per topic: inbox.md (default) plus any <topic>.md
Reviews/        weekly review notes, YYYY-MM-DD.md (latest `## Focus` = current priorities)
Dashboard.md    Obsidian-only live views (Bases + Tasks queries) — agents don't read it
Today.md        Obsidian-only focus view: tasks due/scheduled today, ticked ones stay visible — agents don't read it
Week.md, Week+1.md  Obsidian-only views: this/next week (Mon–Sun) by day, Week.md starts with Last Week; generated by `sb week` — agents don't read them
tools/sb.py     CLI for all task/idea/project operations (see below)
README.md       human guide: setup, manual vs. AI work — agents don't need it
```

## Conventions

1. **One folder per project, named by its slug.** Kebab-case, unique. `general` is a permanent project for tasks that don't belong elsewhere — never leave a task unassigned; default to `general` if unsure. A project exists iff `Projects/<slug>/tasks.md` exists.

2. **`Projects/<slug>/description.md`** (same filename in every project):
   ```markdown
   ---
   status: active | paused | done
   type: app | general | ...
   priority: 1 | 2 | 3        # optional, 1 = highest
   goal: one line, why it matters   # optional
   started: YYYY-MM-DD
   ---

   One-paragraph description.

   Links: [tasks](tasks.md)
   ```
   `type` groups projects (reuse an existing value from other projects when one fits; don't invent one for a one-off). Links are relative Markdown links, not `[[wikilinks]]`, to stay portable.

3. **Task format** (Obsidian Tasks plugin, emoji signifiers after the description):
   ```markdown
   - [ ] task description ➕ YYYY-MM-DD
   - [ ] task with extras ➕ 2026-09-28 📅 2026-10-15 ⏫
   - [x] finished task ➕ 2026-09-28 ✅ 2026-10-02
   ```
   `➕` created, `📅` due, `⏳` scheduled, `✅` done, `❌` cancelled (`- [-]`), priority `🔺⏫🔼🔽⏬`, recurrence `🔁 every week`. Only `➕` is required when adding; add others only when the user gives them. Lowest priority `⏬` means "someday".

   **Scheduled vs. due — use `⏳` by default, `📅` rarely.**
   - `⏳` scheduled = the day the user plans to work on the task. It drives `Today.md` and `daily-plan`, and is freely movable. An unfinished scheduled task shows up under Overdue in `Today.md`, so it isn't lost.
   - `📅` due = a real, external deadline only (missing it has a consequence). Never use it as a placeholder, "finish by" wish or urgency marker; use `⏳` and/or priority for those. Don't set both dates to the same day.
   - Undated tasks are the backlog; they get a `⏳` in the weekly review or in `daily-plan` once the user knows when.

4. **Subprojects.** Optional grouping inside a project: a `## Name` heading in `tasks.md` (and `archive.md`). Tasks above the first heading belong to the main project. Manage via `sb add-task -s`, `sb move`, `sb add-sub`; the archive keeps a task's subproject. The Dashboard groups by folder, then heading.

5. **Open vs. done.** `tasks.md` holds open tasks; `archive.md` holds done ones. When the user ticks a task in Obsidian it lingers as `- [x]` in `tasks.md` until `sb archive` (or any `sb add-task`/`done` on that project) moves it — treat any `- [x]` line as done wherever it is. Never delete task history.

6. **Ideas** are one bullet per idea with a date:
   ```markdown
   - (YYYY-MM-DD) idea text
   ```
   General ideas go in `Ideas/<topic>.md` (`inbox.md` for anything unclear — triage periodically); `sb add-idea --to <topic>` creates a new topic file, only when the user asks for one. Ideas for a specific project go in `Projects/<slug>/ideas.md`.

7. **Change tasks and ideas through `tools/sb.py`, not by hand-editing**, so format and dates stay consistent. Read files directly only for things the script doesn't cover (descriptions, roadmaps, ideas, notes). Read only what's needed; never `archive.md` unless history is asked for.

8. **Routing.** Use the matching skill (see `## Skills`):
   - Task (for a project, or none → `general`) → `add-task`.
   - New project → `add-project`.
   - Idea (general or for a project) → `add-idea`.
   - Note / longer text or list for a project → `add-note`.
   - Finished a task → `complete-task`.
   - Showing tasks (all, or just open) → `show-tasks` / `show-open-tasks`.
   - Overview, "what should I work on next", planning → `overview`.
   - Review, cleanup, planning the week (which project on which day) → `weekly-review`.
   - Planning today / picking today's tasks → `daily-plan`.

9. **Keep entries terse.**

10. **Only edit files in this repo.** Sibling repos (other folders next to this one, e.g. code repos) are read-only from here, in files, shell commands and git alike. Their docs (vision, features, tasks) are changed from a session in that repo; for such work, give the user a ready prompt to paste there. Read them rarely, only when the user asks or the task needs it. If a request seems to need a change elsewhere, say so and stop. `.claude/settings.json` enforces this with deny rules and the sandbox; add new sibling repos there.

## `tools/sb.py`

Run from the repo root as `python tools/sb.py <command>` (the user can use `sb <command>` via `sb.cmd`). Standard library only; `-h` on any command for options.

| Command | Does |
|---|---|
| `add-task <text> [-p proj] [-s sub] [--scheduled D] [--due D (real deadlines only)] [--priority P] [--recur R]` | append open task with ➕ today |
| `edit <proj> <number\|text> -t <new description>` | replace an open task's description, keeping its dates/priority/recurrence |
| `move <proj> <sub\|main> <number\|text> [--to proj2]` | move an open task to a subproject (`main` = none), with `--to` into another project |
| `cancel <proj> <number\|text>` | cancel an open task (`- [-]` with ❌ today, archived; no next 🔁 occurrence); for duplicates or dropped plans, not for finished work |
| `due <proj> <date\|none> <number\|text>` or `due <proj> <date\|none> --before D` | set/clear 📅 on one open task, or on all open tasks due before D |
| `schedule <proj> <date\|none> <number\|text>` or `schedule <proj> <date\|none> --before D` | set/clear ⏳ (the day to work on it; feeds Today.md) |
| `add-sub <proj> <name>` | create an empty subproject |
| `add-idea <text> [-p proj \| --to topic]` | append dated idea to `Ideas/<topic>.md` (default inbox; a new topic creates the file) or the project's ideas.md |
| `add-note <title> -p proj [-b body] [-i item]...` | create `Projects/<slug>/notes/<title>.md` (or append to it); `-i` adds bullets |
| `add-project <name> --type T --description D [--priority 1-3] [--goal G] [--task T]` | create project folder |
| `open [proj...] [--due DAYS] [--stale DAYS]` | numbered open tasks; `--stale`: undated and older than DAYS |
| `show <proj>` | open + done tasks |
| `done <proj> <number\|text>` | complete (✅ today), archive, next 🔁 occurrence |
| `archive [proj...]` | move ticked tasks to `archive.md` |
| `lint [--fix]` | check format; fix archives ticked tasks and fills missing ➕ from git history |
| `overview [--all] [--idle DAYS]` | per project: status/priority/goal, counts, idle flag, top next task; idea counts |
| `week` | regenerate Week.md and Week+1.md (also runs after every other `sb` command) |
| `log [proj...] [--days N]` | tasks completed in the last N days (default 7) |

Project names resolve by exact slug or unique substring.

## Skills

- `add-idea`, `add-note`, `add-task`, `add-project`, `complete-task` — capture/complete via `sb`.
- `show-tasks`, `show-open-tasks` — task listings via `sb`.
- `overview` — project overview, and the entry point for planning/"what next" advice.
- `weekly-review` — cleanup, inbox triage, stale-task pruning, next week's focus and project-per-day plan → `Reviews/`.
- `daily-plan` — pick specific tasks for today from that day's project(s) and schedule them (feeds `Today.md`).
