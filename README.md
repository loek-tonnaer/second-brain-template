# second-brain-template

A plain-Markdown second brain for projects, tasks and ideas. You browse and edit it in [Obsidian](https://obsidian.md), and [Claude Code](https://claude.com/claude-code) works on the same files: it follows `CLAUDE.md` and the skills in `.claude/skills/`. There's no lock-in: everything is `.md` files plus one small Python script.

This repo is only the skeleton. **Don't clone or fork it to use it.** Make your own copy with its own history (see below), so your notes never share history with this repo, or with each other if you keep several vaults (e.g. one personal, one for work).

## Make it your own

1. On GitHub, click **Use this template → Create a new repository** and set it to **Private**. This gives a new repo with a single first commit, no fork link and no shared history.
   Without GitHub (or to host it elsewhere, e.g. your employer's Git server): download the ZIP from **Code → Download ZIP**, unzip it, then run `git init`, `git add -A`, `git commit -m "Initial commit"` and push it wherever you like.
2. Clone **your** new repo and open the folder as a vault in Obsidian (*Open folder as vault*). You need Python 3 (standard library only) and, for the AI part, Claude Code.
3. **Plugins:** in Settings → Community plugins, turn on community plugins, then **Browse** and install and enable **Tasks** and **Obsidian Git**. Their settings come with the repo:
   - Tasks: created date on every new task.
   - Git: auto commit-and-push every 30 minutes. This is what saves and backs up your changes and Claude's; nothing else commits.
   - The **Alt+T** hotkey (*Tasks: Create or edit task*) and relative Markdown links are preset as well.
4. Optionally pin `Dashboard.md`, `Today.md` and `Week.md`.
5. Open the `general` project's `tasks.md`, look at the example tasks, and delete them once the format is clear.

If your copy will hold work notes, check your employer's rules for where such data may live first. Set your work identity in that repo only: `git config user.email you@work.example`.

## Layout

```
Projects/<slug>/   description.md (status, type, priority, goal), tasks.md (open), archive.md (done),
                   ideas.md, notes/, optional ## Subproject headings in tasks.md
Ideas/             general ideas: inbox.md, plus any topic files you add (Ideas/<topic>.md)
Reviews/           weekly review notes; the latest "Focus" section = current priorities
Dashboard.md       live views: projects table, overdue, next 7 days, high priority, stale, recently done
Today.md           today's due/scheduled tasks, plus overdue ones
Week.md, Week+1.md this week and next, by day (generated by `sb week`, which runs after every sb command)
tools/sb.py        the CLI that both you and the AI use
CLAUDE.md          the conventions Claude Code follows; .claude/skills/ has one skill per workflow
```

Dates: `➕` created, `⏳` scheduled (the day you plan to work on it; drives Today and Week), `📅` due (real deadlines only), `✅` done. Priorities `🔺⏫🔼🔽⏬`, where `⏬` means someday.

## What you do vs. what the AI does

**You, in Obsidian:**
- **Add a task:** press **Alt+T** in a project's `tasks.md`. A task typed by hand as `- [ ] ...` also works; the missing date gets filled in at the next cleanup.
- **Finish a task:** tick it. It stays in `tasks.md` until the next cleanup, but the views already treat it as done.
- **Edit freely:** a project's `status`, `priority` (1–3) and `goal`, ideas, notes.

**Claude Code (just ask in plain language):**
- Add tasks, ideas, notes and projects; complete tasks; show open tasks or an overview.
- "What should I work on next?": it starts from a compact overview.
- **Weekly review** ("let's do a weekly review"): cleans up, triages the inbox, prunes stale tasks, flags idle projects, proposes next week's focus and which project to work on each day, then writes a note to `Reviews/`.
- **Daily plan** ("plan my day"): picks today's tasks from the day's project(s) and schedules them, so they show up in `Today.md`.

**Idea topics:** everything goes to `Ideas/inbox.md` unless you ask for a topic: "add this to my books ideas" creates `Ideas/books.md` the first time, and later ideas that fit go there.

## The `sb` script

Run `sb <command>` in the repo folder (Windows, via `sb.cmd`), or `python tools/sb.py <command>` anywhere. Add `-h` to any command for its options.

`add-task`, `add-idea`, `add-note`, `add-project`, `add-sub`, `open`, `show`, `done`, `cancel`, `edit`, `move`, `due`, `schedule`, `archive`, `lint --fix`, `overview`, `log`, `week`

## Customize

- **Keep Claude out of other folders:** `CLAUDE.md` tells Claude to edit only this repo. To enforce that for folders next to it (e.g. your code repos), add deny rules to `.claude/settings.json`:
  ```json
  "deny": ["Edit(//C:/path/to/other-repo/**)"],
  "ask":  ["Read(//C:/path/to/other-repo/**)"]
  ```
- **Your own conventions** (project types, standard subprojects, extra routing) go in `CLAUDE.md`; new workflows go in `.claude/skills/<name>/SKILL.md`.

## Updating from the template

Your copy shares no history with this repo, so updates are copied, not merged. The **system files** are `CLAUDE.md`, `.claude/skills/`, `tools/`, `sb.cmd`, `Dashboard.md` and `Today.md`. Copy the ones you want from a newer version of this repo over yours, and check `git diff` before committing (keep your own `CLAUDE.md` changes). Everything else (`Projects/`, `Ideas/`, `Reviews/`) is your data and is never touched by updates.
